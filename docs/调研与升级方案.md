### 3. 工程化借鉴结论

- **知识库管理**：不要只靠手动改文件，应有文档列表、上传、删除、重新索引。
- **RAG 可观测性**：把命中的文档块、相似度、来源展示给用户，便于判断回答可信度。
- **多路检索**：向量检索之外可增加关键词/BM25 召回，减少纯向量漏检。
- **网络检索扩展**：可增加可选 web search 工具，但需做来源可信度过滤。
- **前端体验**：增加知识库管理页、来源标签、加载态和错误提示。

## 三、工程升级清单

### 后端
1. 路径改为基于项目根目录的绝对路径，避免从不同目录启动时数据不一致。
2. 增加 RAG 配置（top_k、相似度阈值、分块参数）集中管理。
3. 增加向量库统计接口，便于前端展示知识库规模。
4. 优化自定义规则版本号、系统提示词、来源输出。
5. 增加知识库初始化/同步脚本，从 `knowledge_base/` 一键同步并重建索引。

### 前端
1. 新增知识库管理页：文档列表、上传、删除、统计。
2. 聊天页增加“知识库管理”入口。
3. API 增加文档管理封装。
4. 显示来源时附带相似度（后端返回后前端展示）。

### 工程规范
1. 新增 `docs/` 目录保存调研与方案。
2. 更新 README 说明新的数据目录和知识库维护方式。
3. 新增 `knowledge_base/` 作为可版本管理的知识库源文件。
