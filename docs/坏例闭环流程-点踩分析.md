# 坏例闭环流程 · 点踩分析（W8-卡6）

> 目标：让每一条点踩从"用户不爽"变成"评测集防回归"，形成 PDCA 闭环。
> 数据底座：`feedback` 表的 `context_json`（最近 ≤3 轮完整对话）+ `meta_json`（领域/回答路径/trace_id），W8-卡6 起落库。

## 分析流程（每条点踩四步）

1. **取坏例**：管理页或接口拉点踩列表——
   `GET /api/feedback/recent?rating=down`（需管理密码头），或直接查库
   `SELECT * FROM feedback WHERE rating='down' ORDER BY created_at DESC;`
2. **人工归因**：对照该条 `context_json` 里的最近 3 轮对话，判断答歪原因，归入四类之一：
   - **检索没召回**（知识库里其实有，没检到）→ 优先：查切片/索引/混合检索权重
   - **知识库没有**（本来就没有这份料）→ 补官方文档 → 重索引
   - **检索对但生成歪**（料给了没照着说）→ 调提示词/对照阶段 0 溯源方法复验
   - **问题本身超纲**（涉及实时版本号等库外信息）→ 确认拒答话术是否合理
3. **补进评测集防回归**：把坏例问题加工成评测条目，追加到 `backend/eval/eval_set_variants.json`（改写变体，同型不同表述）；属多跳对比类的同步登记给 W8 卡 3 的 `eval_set_agent.json`。
4. **回归验证**：跑评测脚本确认修复后该条通过，且旧分数不回退——修复才算闭环。

## 字段速查

| 字段 | 内容 | 用途 |
|---|---|---|
| `context_json` | `[{role, content}, ...]` 最近 ≤3 轮（含本轮） | 看"之前问了什么导致这次答歪"（多轮语境污染、指代误解） |
| `meta_json.domain` | 领域/kb_id（valorant/law） | 按领域分桶统计坏例率 |
| `meta_json.path` | workflow / agent | 对比两条路径的坏例率；Agent 时代红利 |
| `meta_json.trace_id` | 关联卡 2 Agent 轨迹文件（`backend/data/agent_traces/`） | 点踩 → 回放 Agent 每一步（卡 2 完成前为空，不报错） |

## 维护约定

- 点赞同样存上下文（轻量）：坏例分析时拉 `rating=up` 做好坏对照，避免"把本来就被夸的答法改坏"。
- 旧数据（v3.8~v3.32 期间落库）两列为 NULL，属正常，分析时按"无上下文可用"处理。
