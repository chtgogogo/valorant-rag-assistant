# Docker 部署验证清单（可复跑）

> 适用：全新服务器从零用 Docker 起一套。
> **已用 nginx + systemd 部署的服务器（如 /opt/rag）不要用本 Docker 方式**，
> 直接跳到文末「已部署服务器的升级」章节。
> 前置：Docker Desktop 已启动（`docker ps` 能出列表）；项目根已有 `.env`（含 `ZHIPU_API_KEY`）。

## 1. 构建

```bat
cd /d 项目根目录
docker compose build
```

**预期**：两个镜像 `valorant-rag-backend`、`valorant-rag-frontend` 构建成功，退出码 0。

## 2. 启动

```bat
docker compose up -d
docker compose ps
```

**预期**：两容器 `running`；backend 由 `starting` 变 `healthy`（首次要下载模型，`start_period=120s`）。

## 3. 后端健康检查

```bat
curl http://localhost:8001/health
```

**预期**：`{"status":"ok"}`

## 4. 初始化知识库（首次部署一次即可）

```bat
docker exec valorant-rag-backend python scripts/init_knowledge_base.py valorant
docker exec valorant-rag-backend python scripts/init_knowledge_base.py law
```

**预期**：分别显示 12 文档 112 块 / 6 文档 592 块。

## 5. 真实问答

- 官方直答（零 LLM）：POST `/api/chat/send` 问"游戏里一共有多少个英雄" → 返回"全部英雄（共 29 位）"
- 流式 RAG：POST `/api/chat/stream` 问"暴徒和幻影有什么区别" → SSE sources + token 事件流

## 6. 会话历史恢复

```
curl "http://localhost:8001/api/chat/history?session_id=docker-test-1"
```

**预期**：返回之前两轮问答历史。

## 7. 管理密码门（v3.30）

- 无密码访问 `GET /api/ticket/list` → **403**（锁死）
- 带 `X-Admin-Key: <ADMIN_PASSWORD 的值>` → **200**

## 8. 审计与持久化

- `docker exec valorant-rag-backend sh -c "wc -l /app/backend/data/audit/audit_*.jsonl"`：随问答 +1
- `docker compose restart backend` 后历史仍在（named volume 生效）；`docker compose down -v` 才会清数据（慎用）

## 9. 收尾

```bat
docker compose down
```

## 常见问题

- **首次启动卡 healthcheck**：模型在下载（走 HF 镜像源），`docker logs -f valorant-rag-backend` 看进度；内网环境可从宿主 `D:\huggingface_cache\hub` 把 `models--BAAI-*` 目录 `docker cp` 进容器 `/root/.cache/huggingface/hub/`，然后 compose 里 `HF_HUB_OFFLINE=1`。
- **GPU**：容器默认 CPU。宿主有 N 卡且装好 nvidia-container-toolkit 时把 compose 的 `EMBEDDING_DEVICE` 改 `cuda` 并加 GPU 设备段。
- **端口冲突**：8001/5174 被占时改 compose `ports:` 左侧宿主端口。

## 已部署服务器的升级（nginx + systemd 架构，如 /opt/rag）

> 适用：服务器上已有 nginx 托管 dist + systemd 跑后端的标准部署。
> **不要用 Docker 方式**，两种架构互斥；Docker 仅适用于从零开始的全新服务器。

```bash
cd /opt/rag
# 若曾误用 docker compose 启动过，先清理（没装 docker 会自动跳过，无害）
docker compose down 2>/dev/null || true

# 1. 拉最新代码
git pull

# 2. 补管理密码（现场写入 .env，不进 git；想换密码改这一行的值）
grep -q ADMIN_PASSWORD .env || echo "ADMIN_PASSWORD=CaoHT@2026" >> .env

# 3. 重新构建前端
cd frontend && npm run build && cd ..

# 4. 重启后端
sudo systemctl restart rag-backend

# 5. 初始化知识库（向量库不进 git，服务器上必须初始化！两个领域都要跑；
#    先停后端释放内存，防 2G 机器 OOM；v3.31 起模型优先走本地缓存，不再受
#    hf-mirror 网络抖动拖累，但首次仍需联网下载模型）
sudo systemctl stop rag-backend
PYBIN=$(systemctl cat rag-backend | grep '^ExecStart=' | sed 's/^ExecStart=//' | awk '{print $1}')
$PYBIN backend/scripts/init_knowledge_base.py valorant   # 预期：12 文档，112 块
$PYBIN backend/scripts/init_knowledge_base.py law        # 预期：6 文档 592 块
sudo systemctl start rag-backend

# 6. 验证知识库非空（两个都应 >0）
curl -s "http://127.0.0.1:8001/api/vector/stats?kb_id=valorant" -H "X-Admin-Key: CaoHT@2026"
curl -s "http://127.0.0.1:8001/api/vector/stats?kb_id=law" -H "X-Admin-Key: CaoHT@2026"

# 7. 页面验证
curl -I https://rag.caohaotian.top    # 应 HTTP 200
# 管理门：无密码应 403（旧版是 200）：
curl -s -o /dev/null -w "%{http_code}\n" https://rag.caohaotian.top/api/ticket/list
# 带密码应 200：
curl -s -H "X-Admin-Key: CaoHT@2026" -o /dev/null -w "%{http_code}\n" https://rag.caohaotian.top/api/ticket/list
```

验证通过后浏览器访问 https://rag.caohaotian.top（用域名访问不会有证书警告；用 IP 访问 HTTPS 必然提示"连接不是专用连接"，属正常现象）。

### 常见故障排查

- **知识库为零 / 问答全走兜底**：先跑上面第 6 步验证接口。若为 0，说明服务器上
  向量库没初始化（`.gitignore` 排除了 `backend/data/`，git pull 不会带数据过去），
  重跑第 5 步即可；init 输出逐文档"完成 (N 块)"为成功，出现"失败: ..."把报错
  发出来排查（常见=内存不足未停后端、模型首次下载断网）。
- **工单回流"向量入库失败"**：看后端日志 `sudo journalctl -u rag-backend -n 100
  | grep 向量引擎`。v3.31 之前的版本会看到 hf-mirror 连接超时重试日志（根因=
  模型加载强制联网检查更新）；升级到 v3.31+ 后模型走本地缓存，不再有此问题。
  若日志显示模型本地缓存也没有，先手动跑一次第 5 步让模型下载落缓存。
- **侧栏"百姓法律智能助手"标题发黑看不清**（v3.32.1 已根治）：根因是全站根容器
  未声明默认文字颜色，侧栏信息卡标题漏设 color，继承了浏览器默认黑色。升级到
  v3.32.1+ 即可；若云端仍发黑，先确认已完成 `git pull && cd frontend &&
  npm run build`（截图显示旧版文案"快捷问题见欢迎屏"即说明还在跑旧构建）。

### 本次升级（v3.20~v3.30）新特性速览

- 管理页密码门：工单/知识库/审计接口需 `X-Admin-Key`（未配 `ADMIN_PASSWORD` 时一律 403）
- 工单回流：已解决工单可编辑答案重新回流（幂等替换，不再重复入库）；失败保留输入
- 法律领域：前端领域切换里新增"法律助手"（民法典/刑法含修正案/劳动法/劳动合同法/消保法官方全文）
- 审计新增 token 用量、失败分类、哈希链；`scripts/audit_report.py` 可出汇总报表
- 安全：session_id/kb_id 白名单、鉴权常量时间比较、SSE 断连兜底、BM25 指纹缓存键
