# Docker 部署验证清单（可复跑）

> 每步都是"命令 + 预期"，按序执行即可完整复现 2026-09-25 的真机验证。
> 前置：Docker Desktop 已启动（`docker ps` 能出列表）；项目根已有 `.env`（含 `ZHIPU_API_KEY`）。

## 1. 构建

```bat
cd /d E:\xuexixiangguan\pythonProject\gongcheng\实训毕设无畏契约智能对话小助手
docker compose build
```

**预期**：两个镜像 `valorant-rag-backend`、`valorant-rag-frontend` 构建成功，退出码 0。
首次构建约 3~8 分钟（依赖层 + 前端 npm install）。

## 2. 启动

```bat
docker compose up -d
docker compose ps
```

**预期**：两容器 `running`；backend 的健康状态从 `starting` 变为 `healthy`
（首次启动要下载 bge 模型约 400MB，`start_period=120s` 内完成）。

## 3. 后端健康检查

```bat
curl http://localhost:8001/health
```

**预期**：`{"status":"ok"}`

## 4. 真实问答（走容器内检索+LLM 全链路）

```bat
curl -X POST http://localhost:8001/api/chat/send -H "Content-Type: application/json" -d "{\"session_id\":\"docker-test-1\",\"question\":\"游戏里一共有多少个英雄\",\"kb_id\":\"valorant\"}"
curl -X POST http://localhost:8001/api/chat/stream -H "Content-Type: application/json" -d "{\"session_id\":\"docker-test-1\",\"question\":\"暴徒和幻影有什么区别\",\"kb_id\":\"valorant\"}"
```

**预期**：第一问走官方直答返回英雄总数；第二问流式返回 `event: sources` 与多个 `event: token`。

## 5. 会话历史恢复

```bat
curl "http://localhost:8001/api/chat/history?session_id=docker-test-1"
```

**预期**：返回上面两轮问答的历史消息（刷新/换端不丢会话）。

## 6. 审计文件增长验证

```bat
docker exec valorant-rag-backend sh -c "wc -l /app/backend/data/audit/audit_*.jsonl && tail -1 /app/backend/data/audit/audit_*.jsonl | head -c 400"
```

**预期**：行数随每次问答 +1；最新记录含 `error_class`、`prev_hash`/`self_hash` 等字段。

## 7. 前端页面

浏览器打开 <http://localhost:5174>，发 1-2 轮问答。

**预期**：页面正常渲染；答案逐字流式输出；回答下方带来源；`/api` 请求经 nginx 反代成功（F12 Network 里 `/api/chat/stream` 为 200）。

## 8. 数据持久化（重启不丢）

```bat
docker compose restart backend
curl "http://localhost:8001/api/chat/history?session_id=docker-test-1"
```

**预期**：历史仍在（named volume 生效）。彻底清库用 `docker compose down -v`（会删数据，慎用）。

## 9. 收尾

```bat
docker compose down          # 停止（保留数据卷）
```

---

## 常见问题

- **首次启动卡在 healthcheck starting**：模型在下载（HF 镜像源），`docker logs -f valorant-rag-backend` 看进度；网络差时 `docker compose build` 前设置代理。
- **GPU**：容器内默认 CPU（`EMBEDDING_DEVICE=cpu`）。宿主有 N 卡且装了 nvidia-container-toolkit 时，把 compose 里该变量改为 `cuda` 并加 `deploy.resources.reservations.devices`（需自行验证，未纳入本次清单）。
- **端口冲突**：8001/5174 被占用时改 compose 里的宿主侧端口映射（`ports:` 左边的数字）。
