# 评测集升级方案（v3.3 → v4 评测体系）

> 状态：**已拍板并实施（2026-09-20，v3.4）**——X04 期望=拒答（实测生成层成功拒答）；自审思考=A/B 实测零增益后默认关；温度 0=已强制；三层全部落地。实施结果见 CHANGELOG v3.4。
> 背景：现有评测集 20 题主集 + 8 题变体，在 v3.0~v3.3 迭代中立过功（消融归因、抓出 LLM 调用全挂、GPU 精度回归），但结构上有 8 个盲区，本方案系统性补齐。

---

## 一、现状体检：现有评测集的 8 个盲区

| # | 盲区 | 后果 | 实证 |
|---|---|---|---|
| 1 | **全部单轮**（history 恒为空） | 查询改写——简历核心卖点之一——从未被评测覆盖 | 改写链路仅探针测过一次 |
| 2 | 拒答集仅 3 题且太"假" | 天气/写代码/红烧肉一眼假，拦不住真陷阱 | 拒答 100% 的含金量被质疑 |
| 3 | **缺"半相关陷阱题"** | 最考验系统的题型（相邻领域相似词）零覆盖 | "CS2 的 AK"（KB 里 AK=狂徒别名！检索层极易误召回） |
| 4 | 官方数据直答路径零覆盖 | 英雄列表/武器价格/地图类问题走确定性回答（v3.1 卖点），评测不知道它好不好 | 无任何用例 |
| 5 | Critic 灰区逻辑零覆盖 | 换写法重检索、择优、封顶——全是新代码 | 仅 1 次人工探针 |
| 6 | 题目与知识库同源 | 自写自测的泄漏风险（照着答案出题） | 结构性问题 |
| 7 | 报告只有总分 | 不知道哪类弱、哪次是噪声 | 覆盖率 62.5%→53.1% 无法归因 |
| 8 | 生成指标受温度影响 | LLM_TEMPERATURE=0.2 采样波动 | 同口径两次差 9.4 个百分点 |

---

## 二、目标结构：三层评测体系

```
Layer 1 主回归集（现有 20+8，冻结保留）
   └─ 改库/改代码后必跑，防回归；数字带日期对外引用
Layer 2 扩充集（本次新增 ~30 题，四个分区）
   └─ L2-A 官方数据直答（6 题，脚本自动生成）
   └─ L2-B 黑话别名（8 题，从 aliases.json 反推）
   └─ L2-C 多轮指代（5 题，需 eval 脚本支持 history）
   └─ L2-D 拒答与陷阱（8 题，含半相关陷阱）
Layer 3 专项诊断集（调参时才跑）
   └─ Critic 评审员标注集（10 题）→ 裁决"自审要不要开思考"
```

## 四、Layer 3：Critic 评审员标注集（10 题）——**用数据裁决"自审要不要开思考"**

每题 = (问题，人工给的资料片段，标准答案 sufficient/insufficient)。**资料片段人工构造**（不经过检索），5 题充足、5 题不足，其中至少 4 题是"看起来沾边但答不了"的边缘案例。跑两遍：`LLM_CRITIC_THINKING=1` vs `=0`，比判分准确率与耗时。

**决策规则（先约定后跑数）**：思考版准确率高 ≥10 个百分点 → 自审保留思考；差距 <10 → 自审默认关思考（每题省约 10 秒）。**我的预测：你的直觉对，大概率关**——二元判断任务思考增益通常小，但让数据说话。

## 五、配套机制改进（随评测集一起做）

1. **评测时强制温度 0**：eval 脚本内 `os.environ.setdefault("LLM_TEMPERATURE", "0")`，生成指标不再漂（62.5%/53.1% 之差将消失）；日常对话保持 0.2。
2. **eval 脚本支持 history 字段**（约 10 行改造）：多轮题传入历史。
3. **报告分层**：按类型统计 Hit@5/覆盖/相似度 + P95 延迟 + 设备口径（cuda/cpu）+ Critic 触发次数。
4. **自动生成器**：`gen_official_eval.py` 从 heroes/weapons/maps.json 自动产出 L2-A 题（价格/数量/列表），题与数据永同步。
5. **防泄漏纪律**：新题三种来源全注明（官方 JSON 自动生成 / 黑话表反推 / 人工口语化改写）；KB 大改后 L1 重跑并更新对外数字日期。
