# 卡 #11（RAG）：安检 L1 十二项补全 + 前端 markdown XSS 专项（用户授权"修到底"）
- 背景：卡#9 只填了安检报告第 4/11 两项，本卡把 RAG 的 L1 十二项补全（其中 async 项卡#10 已做，直接引用），并专项核查一个高风险面。
- **专项（最重要）：前端 markdown XSS**。ChatPage.vue 用 `renderMarkdown()` 生成 html 塞进 `v-html`——渲染内容=LLM 输出+知识库文档内容，两者都可能含恶意 `<script>/<img onerror>/javascript:` 链接（知识库文档可被任何人上传！）。核查：①读 renderMarkdown 实现（自写正则还是库）；②构造含 `<img src=x onerror=alert(1)>` 的知识库文档上传→提问→检查渲染产物是否含未转义的 onerror（前端编译产物走查或 jsdom 思路，无法开浏览器则以"渲染函数输出不含未转义事件属性"为准）；③若确认无净化→修复：引入 DOMPurify（`npm install dompurify`，这是有充分理由的新依赖，允许）在 v-html 前净化，或 renderMarkdown 末尾统一 sanitize；④修复后同样构造验证：净化后输出不含事件属性/javascript: 协议。
