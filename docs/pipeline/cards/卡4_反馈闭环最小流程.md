# 卡 #4：用户反馈闭环最小流程（点赞点踩）
- 目标：用户能对每条 AI 回复点 👍/👎，反馈落到本地库，为 badcase 回流（卡#5）提供数据源。
- 涉及文件：
  - 新建 `backend/routers/feedback_router.py`
  - 新建 `backend/services/feedback_service.py`
  - `backend/main.py`（注册 router，一行 include）
  - `frontend/src/components/ChatPage.vue`（assistant 消息气泡下加按钮）
- 前置依赖：卡#2 已完成（同文件 ChatPage.vue，避免编辑冲突）
- 实现要点：
  1. 存储：新建 SQLite `backend/data/feedback.db`，表 `feedback(id INTEGER PRIMARY KEY AUTOINCREMENT, session_id TEXT, question TEXT, answer TEXT, rating TEXT CHECK(rating IN ('up','down')), created_at TEXT DEFAULT (datetime('now','localtime')))`；建表逻辑放 service 的 init，随 lifespan 调用（参照 `ticket_service`/`tickets.db` 的现有模式，先读它再写）；
  2. 接口：`POST /api/feedback`，body `{session_id, question, answer, rating}`，重复评价同一 answer 时覆盖原记录（以 question+answer 摘要判重即可）；返回 `{ok: true}`；
  3. 前端：每条 assistant 消息下方两个小按钮 👍/👎；点击调 POST；已评价后按钮置灰不可重评；不需要评论框（YAGNI）；
  4. 不加统计接口、不加管理页（卡#6 范围只含工单+审计，反馈列表后续再说）。
- 基线（开工前记录）：跑 `python backend/scripts/evaluate_rag.py` 的 L1 评测（或项目现有评测入口，先读 scripts 确认命令），记录命中率数字到卡文件底部——本卡不动检索链路，完成后复跑不应低于基线 1 个点。
- 验收（怎么算做完）：
  - `curl -X POST localhost:8000/api/feedback -H "Content-Type: application/json" -d '{"session_id":"t1","question":"q","answer":"a","rating":"down"}'` 返回 ok；再用 sqlite3/命令行查 feedback 表有该行；
  - 前端页面上 👍/👎 可点、点击后置灰、刷新页面后按钮状态允许重置（状态持久化不在本卡范围）；
  - 复跑 L1 评测不低于基线-1pt，数字贴回。
- 禁止：不动检索/改写/rerank 任何逻辑；不动 tickets.db；不加用户鉴权；不引入新 Python 包（sqlite3 标准库足够）。
- 完成后动作：贴 curl 与评测输出；更新台账卡#4 行；返回 3 行以内摘要。
