## 第 4 项：鉴权矩阵 ✅

**问题**：`/api/audit/recent`（backend/main.py）是全项目唯一未挂 `verify_api_key` 的业务路由，却返回全部用户问答原文（问题、改写、来源、答案、耗时）。

**修复**：该路由补 `dependencies=[Depends(verify_api_key)]`，与文档/向量/对话/工单/反馈/领域六个路由完全同款。

**放行逻辑链（本地行为零变化的依据）**：
1. `backend/config/settings.py:129`：`AUTH_ENABLED = os.getenv("AUTH_ENABLED", "0") == "1"` —— 环境变量未设时默认 `"0"`，即**默认关闭**；
2. `backend/utils/auth.py` `verify_api_key()`：第一行 `if not AUTH_ENABLED: return` —— 关闭时**直接放行**，不碰请求头；
3. 因此挂上依赖后，默认配置下所有请求（含前端管理页 AdminPage 的审计表 `getRecentAudit`）行为零变化；仅当 `.env` 显式设 `AUTH_ENABLED=1` 时，无/错 `X-API-Key` 才返回 401。

**证据（8002 验证实例实测，用户 8001/5174 现役实例未动）**：
- `AUTH_ENABLED=1`（另设 `API_KEYS=testkey123`）启动：
  - 无 key：`HTTP/1.1 401 Unauthorized` + `{"detail":"API Key 无效或缺失"}`
  - 带正确 key：`HTTP/1.1 200 OK`（26921 字节真实审计数据）
- 默认（不设 AUTH_ENABLED）重启同端口：无 key `HTTP_CODE=200 SIZE=26921B`，`{"code":200,"msg":"success","data":[...]}` 正常返回。

**残留风险**：鉴权为全局开关（全开/全关），无按角色的细粒度控制；管理页自身仍依赖"本地演示"定位，运营后台正式化时依赖后续用户体系（与回看报告 backlog ②同源）。

## 第 11 项：死代码 ✅

**问题**：`backend/services/chat_service.py` 的 `test_llm_call(question)`：形参是 `question`，函数体却引用未定义的 `question_for_prompt`，一调用必崩 `NameError`；唯一调用方是 `backend/routers/chat_router.py` 的 `GET /api/chat/test_llm` 路由（可达，属随时可触发的故障点）。

**修复**：
1. 删除 `test_llm_call` 整个函数（含注释头）；
2. 删除 `GET /api/chat/test_llm` 死代码路由（卡片文件清单未列 chat_router.py，但它是死链唯一调用方，函数删除后留着即"调用必 ImportError"暗雷，故随链一并删除——已在 CHANGELOG v3.12 注明）；
3. **保留** `GET /api/chat/test`（模块加载测试）：前端 ChatPage.vue 挂载时调它做后端在线检测（`backendOnline`），是活代码；
4. **前端零改动（核查结论）**：`grep -rn "测试大模型\|test-llm\|test_llm\|testLlm\|testLLM" frontend/src` 零命中——卡片预设的"前端残留调用死函数的按钮"实际不存在；`api.js` 的 `testChat()` 调的是 `/chat/test` 而非 `/test_llm`，与死代码链无关，按外科修改原则不动。

**证据**：
- `grep -n "test_llm_call\|question_for_prompt" backend/services/chat_service.py`：无函数残留；`question_for_prompt` 仅剩主流程 10 处正常变量引用（chat_single_turn / chat_single_turn_stream 内，官方别名替换结果）；
- 后端全局 `grep -rn "test_llm" backend/ --include="*.py"`：零代码命中；
