## 第 7 项专项：前端 markdown XSS（本卡核心，已修复）

### 漏洞确认（修复前）

**渲染管线**：`frontend/src/components/ChatPage.vue` 的 `renderMarkdown()`（marked v18.0.5，`{breaks:true, gfm:true}`，marked 自 v0.7 起废弃、后续版本移除了 sanitize 能力，**不做任何净化**）→ 产物赋给 `msg.html` → 模板 `<div class="md-body" v-html="msg.html">`（ChatPage.vue:141）直插 DOM。

**攻击面成立条件**：渲染内容 = LLM 输出 + 知识库文档内容（检索片段进入 prompt、答案转述可能携带原文标签），而**知识库文档可被任何人经 `/api/document` 上传**——恶意文档被提问命中后，其携带的 `<img src=x onerror=...>` 类载荷会随答案原样进 `v-html` 执行。

**复现证据（jsdom 思路，卡文件明示允许；复用仓库内同版本 marked@18.0.5 + dompurify@3.4.15，与 ChatPage.vue 完全相同的 parser 配置）**——恶意载荷：

```
<img src=x onerror=alert(1)>

<script>alert(2)</script>

[点我](javascript:alert(3))

<iframe src="https://evil.example"></iframe>

<a href="javascript:alert(4)">x</a>
```

修复前渲染函数输出（直进 v-html，**全部未净化**）：

```html
<img src=x onerror=alert(1)><script>alert(2)</script><p><a href="javascript:alert(3)">点我</a></p>
<iframe src="https://evil.example"></iframe><p><a href="javascript:alert(4)">x</a></p>
```

→ **漏洞确认**：onerror 事件属性、`<script>`、`<iframe>`、`javascript:` 协议链接全部原样保留，注入即执行。

### 修复（v3.13）

1. `frontend` 新增唯一依赖 **dompurify 3.4.15**（`npm install dompurify`，卡文件明示允许）；
2. `ChatPage.vue` `renderMarkdown()` 末尾统一净化：`return DOMPurify.sanitize(raw)`——所有进入 `v-html` 的 markdown 产物（流式增量/兜底/降级/历史恢复/撤回恢复共用此函数）一处收口；
3. 顺带闭环同文件唯一另一处**动态内容** `v-html`：欢迎屏快捷问题 `q.emoji`（来自后端领域配置 yaml）同样过 `DOMPurify.sanitize`（现配置均为纯文本表情 📦，净化后渲染零变化）；`cat.icon`/`VALORANT_QUICK` 的 SVG 为组件内开发者写死的字面量（可信静态内容），不改并在此注明。

### 修复后验证（同一载荷、同一渲染函数体）

```html
<img src="x"><p><a>点我</a></p>
<p><a>x</a></p>
```

逐载荷断言（全部 PASS，脚本退出码 0）：
- PASS｜onerror 事件属性被剥离（img 标签本体保留，图片功能不误伤）
- PASS｜`<script>` 整块移除

- PASS｜`<iframe>` 整块移除
- PASS｜字面 `<a>` 的 `javascript:` href 被剥离

**不误伤回归**：正常业务 markdown（标题/加粗/行内代码/外链/表格/引用/列表）经净化后全部保留，渲染结果与修复前一致。

**编译与产物走查**：`npm run build` 通过（`✓ built in 569ms`，exit 0；警告为 element-plus 依赖 @vueuse/core 的既有 PURE 注解提示，与本改动无关）；`dist/index.html` 实际引用的新产物 `assets/index-Dql4JR3I.js` 内含 DOMPurify 与 7 处 sanitize 调用（dist 中其余同名 hash 产物为 09-04~09-22 历史构建遗留、index.html 未引用，不构成暴露面）。
