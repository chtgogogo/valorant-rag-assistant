# cpolar 双项目同时部署说明

> 目标：失物招领系统 + RAG 无畏契约智能对话小助手同时上线，把本机服务发布成公网可访问的远程演示地址。

## 一、端口规划（关键）

两个前端默认都用 5173，两个后端默认都用 8000，同时启动会冲突。建议按下表拆分：

| 项目 | 前端端口 | 后端端口 | 说明 |
|------|----------|----------|------|
| 失物招领系统 | 5173 | 8000 | 保持原配置不变 |
| RAG 无畏契约助手 | 5174 | 8001 | 本项目已改好 |

RAG 项目已经修改：

- `frontend/vite.config.js`：`port: 5174`、`strictPort: true`、`allowedHosts: true`，`/api` 代理到 `http://127.0.0.1:8001`
- `backend/config/settings.py`：默认 `SERVER_PORT` 改为 `8001`

如果 `.env` 里写了 `SERVER_PORT=8000`，要改成 `8001` 或删掉这一行。

## 二、本地启动顺序

1. 启动失物招领后端（8000）
2. 启动失物招领前端（5173）
3. 启动 RAG 后端（8001）
4. 启动 RAG 前端（5174）

也可以直接双击 `gongcheng` 目录下的 `启动两个项目.bat`，一次拉起四个窗口。

## 三、cpolar 隧道怎么填

失物招领已经有一条隧道，保持不动即可：

| 字段 | 填法 |
|------|------|
| 隧道名称 | 失物招领（已有） |
| 协议 | HTTP |
| 本地地址 | `127.0.0.1:5173` |
| 地区 | China Top / cn_top |
| 状态 | 启用 |

新建 RAG 的隧道：

| 字段 | 填法 |
|------|------|
| 隧道名称 | `rag-valorant` 或 `无畏契约RAG` |
| 协议 | HTTP |
| 本地地址 | `127.0.0.1:5174` |
| 地区 | China Top（cn_top） |
| 备注 | 指向 RAG 前端，后端由 Vite 代理转发 |

创建成功后 cpolar 会给一个类似 `https://xxxx.r2.cpolar.top` 或 `https://xxxx.cpolar.cn` 的公网地址。把这个 HTTPS 地址发给需要远程体验的人即可（注意免费版地址重启会变，见第六节）。

## 四、cpolar 免费版能不能同时开两个？

可以。cpolar 免费版每个 cpolar 进程支持 4 个隧道，1 个在线进程。当前配置里已有：

- 其他隧道（例如远程桌面等，按需保留）
- 失物招领（HTTP 5173）

再加一条 RAG（HTTP 5174）仍在上限内。

## 五、部署前检查清单

- [ ] 失物招领前端确实运行在 5173
- [ ] 失物招领后端确实运行在 8000
- [ ] RAG 前端确实运行在 5174
- [ ] RAG 后端确实运行在 8001
- [ ] 浏览器分别访问 `http://localhost:5173` 和 `http://localhost:5174` 都正常
- [ ] cpolar 两条 HTTP 隧道都已启用
- [ ] 用 cpolar 的公网地址分别访问两个项目，确认能打开
- [ ] RAG 先问一个问题，把 embedding / 重排模型预热好，避免演示时第一次回答等待过久
- [ ] 演示期间不要关闭四个命令行窗口和 cpolar 进程

## 六、常见问题

### 1. 公网打开显示 Vite 的 Blocked request

把 `frontend/vite.config.js` 的 `allowedHosts` 设为 `true`，不要只写死某个 ngrok 域名。本项目已改好。

### 2. 公网打开后接口 404 / 500

检查 RAG 后端是否在 8001，且 `frontend/vite.config.js` 代理目标是否为 `http://127.0.0.1:8001`。

### 3. 两个项目互相抢端口

用 `netstat -ano | findstr :5173`、`:5174`、`:8000`、`:8001` 查看占用，停掉占错端口的进程，再重新启动。

### 4. cpolar 地址每次重启都会变

免费版随机域名会变化。演示前重新生成地址，或者升级 cpolar 保留固定二级域名。

## 七、为什么加载很慢，以及怎么提速

### 1. 页面打开慢

Vite 开发模式会按模块逐个加载前端依赖，Element Plus 文件很多；cpolar 免费版带宽只有 1Mbps，所以第一次打开会非常慢。

**解决：用生产构建 + preview 代替开发模式。**

RAG 项目已经配置好 `preview`，启动方式：

```powershell
cd frontend
npm run build
npm run preview
```

然后 cpolar 的 RAG 隧道指向 `127.0.0.1:5174`。生产构建只有 1MB 左右，体验会明显快很多。

如果使用了仓库外的一键启动脚本，请同步把 RAG 前端改为 `npm run build && npm run preview`。

### 2. 第一次提问慢

第一次提问需要加载：

- embedding 模型 `bge-small-zh-v1.5`（约 92MB）
- BM25 分词索引
- reranker 模型 `bge-reranker-base`（约 1.08GB）

冷启动通常需要 15～30 秒，之后同一进程内会快很多。

**解决：演示前先预热。**

后端启动后，浏览器打开一次：

```text
http://127.0.0.1:8001/api/chat/warmup?kb_id=valorant
```

看到 `retrieval model warmup ok` 或返回 JSON 即表示模型已加载。之后第一次真实提问就不会再等模型加载。

### 3. 每次回答都慢

预热后，检索 + 重排大约 1～2 秒，剩余时间主要是 GLM 生成答案。答案越长，生成越慢。

可以在 `.env` 里加这些演示参数：

```env
LLM_MAX_TOKENS=512
RAG_RERANK_CANDIDATES=4
```

含义：

- `LLM_MAX_TOKENS=512`：限制回答长度，明显缩短生成时间，适合公网演示
- `RAG_RERANK_CANDIDATES=4`：减少进入 CrossEncoder 的候选数，重排更快

如果演示环境特别卡，可以临时关闭重排：

```env
RAG_RERANK=0
```

注意：关闭重排后，无关问题的拒答能力会下降，只建议在非常卡的时候临时用。

### 4. 仍有明显卡顿

- 确认没有其他大程序占满 CPU / 内存
- 确认 cpolar 隧道指向 5174，而不是 dev 模式或错误端口
- 确认后端跑在 8001，且前端代理指向 8001
- 演示前先预热一次，不要等观众到了才第一次启动
